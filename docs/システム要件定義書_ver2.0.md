# システム要件定義書 ver2.0

**案件の発生から契約までの営業活動を把握・共有する進捗管理の拡張**

- **版**: 2.0  
- **前提**: [要件定義.md](./要件定義.md)（ver1）で定義した工事業向け業務管理・経理アプリ（kannri-app）をベースとする。  
- **目的**: 進捗管理機能を拡張し、「問い合わせ発生 → 担当割当 → フォロー・商談 → 見積・契約」までの営業活動を一覧・共有できるようにする。

## 2. 追加する機能一覧（進捗管理の拡張）

以下は **ver2.0 で追加を想定する機能**です。出典：進捗管理「案件の発生から契約までの営業活動を把握・共有」の要件（機能①）。

| No. | 追加機能 | 概要 |
|-----|----------|------|
| 2-1 | **TOP画面で進行中案件を状態別に一覧表示** | 営業が進行中・商談中の案件を状態別にTOPで一括確認。スケジュール管理・セルフマネジメントの支援。 |

| 2-3 | **既存顧客のリピート処理** | 既登録顧客からの問い合わせは顧客情報を即検索。「リピート」ボタンで連絡先等を自動転記し、問い合わせ内容だけ入力して登録完了。 |
| 2-4 | **担当割当時のメール通知** | 問い合わせ登録・担当者割り当て時に、顧客名・住所・電話・問い合わせ内容を担当者の携帯メールに送信。電話に出られない場合の迅速対応を支援。 |

| 2-6 | **発生元（媒体）の登録** | 案件の発生元・媒体（例：ホームページ・紹介・チラシ）を登録。集計して効果の高い宣伝計画に活用。 |

| 2-8 | **失注記録** | 失注時の理由・見積金額などを詳細入力。見積内容と組み合わせて今後の営業に活用。 |
| 2-9 | **月次売上目標と達成率** | 営業担当ごとに「受注金額」「完工金額」の月次目標を登録。リアルタイム集計で目標達成率を表示。 |
| 2-10 | **部門別フロー（案件発生〜契約）** | 営業：問い合わせ登録→担当割当→フォロー・商談→見積→見積報告→契約。店長：進捗管理・見積承認・売上管理。事務：顧客一覧・連絡調整。経理：会計・請求まわり。 |

## 2B. 追加する機能一覧（入金管理・機能③）

以下は **ver2.0 で追加を想定する入金管理機能**です。キャッシュフローの健全化と入金管理の効率化を目的とする。

### 入金管理の追加機能（箇条書き）

- **キャッシュフローの現場単位チェック**
  - 工事ごとの入出金を現場（案件）単位で管理し、会社全体のキャッシュフローの健全性を保つ。
  - 数ヶ月先の資金繰り予定を明確に把握できるようにする。

- **入金予定の作成・管理**
  - **契約時に入金予定を作成**：契約処理から予算確定までの間に、顧客からの入金予定（日付・金額）を登録する。
  - **入金予定未確定時の作業停止**：入金予定が適切に設定されていない場合、予算申告以降の次の作業への進行をシステム的に止める。
  - **入金予定の変更制限**：入金予定日や金額の変更は、権限を持つ責任者のみが入力可能とし、未承認の変更を防ぐ。

- **入金状況の監視・警告**
  - **未回収・入金遅れの警告表示**：TOP画面で、当日から1週間分の入金予定のうち、期日を過ぎても入金されていないものを一覧表示する。契約詳細を開かずに現在の入金状況を把握できるようにする。
  - **入金相違の警告**：入金実績を入力した際、入金予定と実績（日付・金額）に相違がある場合は、承認されるまで警告表示で知らせる。

- **資金繰り把握**
  - 各工事の入金予定日・入金額を集計し、複数ヶ月先の資金繰り状況を把握できるようにする。

- **経理資料の作成・管理**
  - **入金・支払などの経理資料の簡単作成**：顧客からの入金や協力業者への支払いに関する経理事務を効率化し、月次決算の短縮とコスト削減に貢献する。
  - **ローン情報の記録**：入金情報に、銀行振込・現金受領に加えて、ローンに関する情報も記録できるようにする。
  - **顧客への請求書発行**：顧客向けの請求書を印刷・発行する機能を用意する。

- **部門別ワークフロー（入金まわり）**
  - **営業**：入金予定の作成、入金遅れの警告受信。
  - **店長**：入金予定の変更、入金遅れ・入金相違・未回収の警告受信。
  - **経理**：入金実績の記録。
  - **事務**：入金完了の確認や補助業務。

## 2C. 追加する機能一覧（原価・支払・帳票・スケジュール連携など）

以下は、各参考資料（機能④原価管理、⑤⑥顧客管理、⑦見積、⑧スケジュール、⑨検索・印刷など）から読み取った**入金・支払・原価まわり**の追加機能を箇条書きでまとめたものです。**既存**でできることと**追加**で必要なことを区別して記載します。

### 原価管理・業者請求・支払（機能④ 原価管理 より）

- **【追加】発注書を元にした請求書の自動入力**
  - 工事業者から届く請求書の内容を、対応する発注書作成時に入力した情報から検索し、ボタン操作で転記入力する。多数案件での請求書入力の手間削減と入力ミス抑制。
- **【追加】請求書付き発注書の発行**
  - 発注書に請求書を付属させ、発注していない内容の請求が計上されることを防ぐ。業者の別途請求書発行の手間も省く。
- **【既存の強化】オンラインでの請求書回覧・確認**
  - 経理が入力した業者からの請求書内容を、営業がオンラインでリアルタイムに確認する。書類の物理的な回覧を不要にし、確認スピードを上げる。
- **【追加】確認が必要な請求書の自動ピックアップ**
  - 発注データとの相違があるなど、特に確認が必要な請求書のみを自動抽出し、確認作業を省力化する。
- **【追加】現場経費の自動原価計上**
  - 現場で発生した現金精算処理を原価計算と一体化し、自動的に案件の原価として計上する。すべての費用を正確に原価に反映し、粗利益の算出精度を高める。
- **【既存の強化】効率的な支払処理**
  - 未払い請求書一覧から、営業担当者によるチェック状況を確認したうえで、ボタン操作で支払処理を実行する。支払業務の迅速化とオペレーションミスの軽減。
- **【追加】支払確定**
  - 支払処理が正常に完了したことを確定し、記録する機能。
- **【追加】追加予算の承認ワークフロー**
  - 工事中の追加発注が粗利益に与える影響を管理するため、追加発注時は責任者への申告と承認を必須とする。計画外のコスト増大を防ぎ、予算管理を強化する。
- **【追加】原価確定処理**
  - 一つの現場に関連するすべての請求書チェックが完了した時点で、最終原価を確定する。この時点で最終粗利益が確定し、案件の収益性を正確に把握する。
- **部門別（原価・支払まわり）**：営業＝追加予算申告。店長＝追加予算承認。事務＝現場経費精算。経理＝請求書入力・請求書チェック・原価確定・支払処理・支払確定。

### 顧客入金・請求・可視化（機能⑤⑥ 顧客管理 より）

- **【既存の拡張】入金関連データの管理・検索**
  - 入金完了日・請求金額・借入先・借入金額・受注金額・完工金額などを記録し、金額や日付で顧客・案件を検索できるようにする。
- **【追加】入金情報の詳細登録・編集**
  - 各契約・請求書に対する入金情報（入金日・入金額・入金方法・入金元口座など）を詳細に登録・編集する。一部入金・分割払いにも対応し、複数回の入金記録を管理する。
- **【追加】請求書発行・管理とステータス追跡**
  - 発行済み請求書を一覧で管理し、ステータス（未発行・発行済み・支払済み・期限切れなど）を追跡する。修正・再発行・キャンセルにも対応する。
- **【追加】入金状況の可視化と進捗管理**
  - 契約ごと・顧客ごとの入金状況（総請求額に対する入金額・未入金残高・遅延状況）を一覧で確認するダッシュボード。入金ステータス（未入金・一部入金・入金完了・遅延など）の更新・管理。
- **【追加】未入金催促・リマインダー**
  - 支払期日を過ぎた未入金に対して催促メールや通知を送信する。支払予定日のリマインダーを設定し、担当者や顧客に通知する。
- **【追加】入金関連レポート・分析**
  - 指定期間の入金実績・未入金残高・平均回収期間などを集計し、グラフや表で表示する。顧客属性や契約内容と入金状況の相関分析で経営判断を支援する。

### 見積と入金予測・予算連携（機能⑦ 見積作成 より）

- **【追加】受注見込みと予算の連携**
  - 見積内容が当月の「受注見込み額」に自動反映される。集計された受注見込みで店長が店舗予算の達成度をリアルタイムにチェックできる。予算作成時に見積が連動し、将来の入金計画を立てやすくする。
- **【既存の強化】見積承認プロセス**
  - 完成した見積を店長などの責任者に申告し、承認を得る。積算ミスによる粗利益低下を未然に防ぎ、承認のない見積書は印刷不可とする。
- **【追加】標準単価表の登録・共有と過去見積の活用**
  - 過去の見積データや標準単価表を全社で共有し、スピーディーかつ正確な見積作成に活用する。
- **【追加】見積明細の端数自動処理**
  - 見積価格の端数を設定単位に応じて自動で切り上げ・切り捨てし、請求金額の標準化と経理・入金照合の手間を減らす。
- **【追加】経費割合の事前設定と掛け率・値引率入力補助**
  - 現場経費・養生費・通信費などの経費割合を事前設定し、希望する粗利率や掛け率に基づいて見積価格を自動計算する。
- **【追加】採用した見積書の保存**
  - 数回の修正・変更のうえ最終採用された見積書を識別して保存し、請求書の正確性と入金照合の基盤とする。

### スケジュール・カレンダー連携（機能⑧ スケジュール より）

- **【追加】カレンダーでの入金予定表示**
  - 進捗別一覧に加え、「時系列」のカレンダー表示を追加し、**入金予定**をアイコン付きで表示する。訪問予定などとあわせて日々の予定を一覧で把握できるようにする。
- **【追加】「本日の予定」への入金予定の反映**
  - 当日のスケジュール・タスク一覧である「本日の予定」に入金予定を表示し、完了状況の確認も可能にする。複数担当者がいる場合は、入金予定を含むスケジュールの共有にも対応する。

### 帳票・検索・設定（機能⑨ 検索・印刷 より）

- **【追加】入金・支払まわりの帳票出力とダウンロード**
  - 入金管理に特化した帳票として、**入金予定一覧**・**入金実績一覧**・**支払先行一覧**・**未収・未払い一覧**などを出力する。印刷に加え、Excel 等の形式でダウンロード可能にし、加工しやすくする。
- **【既存の拡張】多様な条件での検索**
  - 請負金額（工事金額）や地域などで顧客・案件を絞り込み、経理関連の通知送付時に検索結果から一括で宛名ラベルを印刷できるようにする。
- **【追加】業態に合わせた設定**
  - 「予算確定前の発注処理を許可するか」「原価の計算方法」など、コスト・発注まわりの詳細設定を可能にする。
- **【追加】業者ラベル印刷**
  - 指定月に「支払のある業者」を支払情報からピックアップし、宛名ラベルを印刷する。業者評価の記録・共有により、発注・支払先の選定にも活用する。

## 3. 既存機能と追加機能の対応

「既存でどこまでできているか」と「何を足すか」を対応付けました。

| 追加機能（上記 No.） | 既存での状況 | 追加で必要なこと |
|----------------------|--------------|------------------|
| 2-1 TOPで進行中案件を状態別一覧 | カレンダーで日付ベース表示あり。状態別の一覧・フィルタは案件一覧で一部可能。 | TOP専用の「進行中・商談中」など状態別ウィジェット/一覧。必要に応じてステータス区分の見直し。 |
| 2-2 問い合わせ登録 | 現状は直接「案件」登録。問い合わせ（リード）段階のエンティティなし。 | **問い合わせ（inquiry/lead）の登録フローとテーブル**。問い合わせ→案件の紐付け。 |
| 2-3 リピート処理 | 顧客マスタから選択して案件作成は可能。 | 「リピート」ボタンで顧客情報を自動転記するUI。既存顧客の検索しやすさの強化。 |
| 2-4 担当割当時のメール通知 | なし。 | 問い合わせ登録/担当割当時のメール送信（Supabase Edge Function または外部サービス連携）。 |
| 2-5 電話着信・クレーム表示 | なし。 | 着信履歴の取り込み（電話連携API等）とTOP表示。クレームフラグ・未応答の警告表示。 |
| 2-6 発生元（媒体）の登録 | なし。 | **発生元マスタおよび案件/問い合わせへの発生元ID**。集計画面。 |
| 2-7 フォロー履歴・商談内容の把握 | 案件の備考・メモ程度。履歴としての構造化なし。 | **フォロー履歴（活動ログ）テーブル**。日時・内容・担当者。一覧・検索。管理者向けダッシュボード。 |
| 2-8 失注記録 | ステータス「キャンセル」のみ。理由・見積金額などの構造化なし。 | **失注記録テーブル**（理由・見積金額・日付等）。案件または見積との紐付け。 |
| 2-9 月次売上目標・達成率 | 売上実績の集計はあり。目標値・達成率はなし。 | **担当者別月次目標テーブル**。受注金額目標・完工金額目標。画面で達成率表示。 |

## 5. Supabase 追加テーブル案

ver2.0 の追加機能を実現するための **新規テーブル案**です。実装時に名称・項目は調整してください。

### 5.1 問い合わせ（inquiries）

問い合わせ（リード）を案件の前段階として管理するため。

| 項目（案） | 型 | 説明 |
|------------|-----|------|
| id | uuid, PK | 主キー |
| customer_id | uuid, FK → customers | 既存顧客（任意。新規の場合は後で顧客登録して紐付け） |
| contact_name | text | 連絡先氏名（顧客未登録時用） |
| contact_phone | text | 電話番号 |
| contact_address | text | 住所（任意） |
| inquiry_content | text | 問い合わせ内容 |
| staff_id | uuid, FK → staff | 担当者（割当先） |
| origin_id | uuid, FK → origins（後述） | 発生元（任意） |
| status | text | 例：未対応 / 対応中 / 見積済 / 受注 / 失注 |
| project_id | uuid, FK → projects, nullable | 案件化した場合の案件 ID |
| created_at, updated_at | timestamptz | 作成・更新日時 |
| created_by | uuid, FK → auth.users | 登録者 |

- 既存の「案件登録」は、問い合わせから「案件化」するフローと、従来どおり直接案件登録の両方を想定。

### 5.2 発生元マスタ（origins）

媒体・発生元をマスタで持つ。

| 項目（案） | 型 | 説明 |
|------------|-----|------|
| id | uuid, PK | 主キー |
| name | text | 発生元名（例：ホームページ、紹介、チラシ） |
| display_order | int | 表示順 |
| created_at, updated_at | timestamptz | 作成・更新日時 |

- projects に `origin_id`（FK → origins）を追加するか、inquiries のみに持たせるかは運用に合わせて選択。

### 5.3 フォロー履歴（inquiry_follow_ups または activity_logs）

問い合わせ・案件に対するフォロー・商談内容の履歴。

| 項目（案） | 型 | 説明 |
|------------|-----|------|
| id | uuid, PK | 主キー |
| inquiry_id | uuid, FK → inquiries, nullable | 問い合わせ（問い合わせ単位で管理する場合） |
| project_id | uuid, FK → projects, nullable | 案件（案件単位で管理する場合） |
| activity_type | text | 例：電話 / 訪問 / メール / 商談 |
| content | text | 内容メモ |
| activity_at | timestamptz | 実施日時 |
| staff_id | uuid, FK → staff | 対応担当者 |
| created_at | timestamptz | 登録日時 |

- 問い合わせと案件の両方に紐付けるか、どちらか一方に紐付けるかは運用で決定。

### 5.4 失注記録（project_cancellations または cancellation_records）

失注理由・見積金額などを構造化して保存。

| 項目（案） | 型 | 説明 |
|------------|-----|------|
| id | uuid, PK | 主キー |
| project_id | uuid, FK → projects | 案件（または estimate_id でも可） |
| reason | text | 失注理由（選択または自由入力） |

| proposed_amount | numeric | 見積金額（任意） |
| cancelled_at | date | 失注日 |
| created_at, updated_at | timestamptz | 作成・更新日時 |

- 既存の projects.status = 'cancelled' と併用。失注時にこのテーブルに 1 件登録する想定。

### 5.5 担当者月次目標（staff_monthly_targets）

月次で受注金額・完工金額の目標と達成率計算用。

| 項目（案） | 型 | 説明 |
|------------|-----|------|
| id | uuid, PK | 主キー |
| staff_id | uuid, FK → staff | 担当者 |
| year_month | date または int | 対象年月（例：2025-02-01 または 202502） |
| order_amount_target | numeric | 受注金額目標 |
| completion_amount_target | numeric | 完工金額目標（任意） |
| created_at, updated_at | timestamptz | 作成・更新日時 |

- 達成率は、既存の project_sales や projects の完了日・受注日などから集計して表示。

### 5.6 電話着信・クレーム（2-5）について

- 着信履歴は **外部の電話連携APIやPBX** から取り込む想定のため、Supabase には「着信ログ用」テーブルを 1 本用意する形が考えられます。
- 例：`call_logs`（着信日時・顧客/電話番号・応答有無・クレームフラグ・担当者 など）。連携方式が決まり次第、項目を確定。

### 5.7 入金予定（deposit_schedules）【入金管理・機能③】

契約時に入金予定を登録し、未確定時は次の作業へ進めないようにするため。

| 項目（案） | 型 | 説明 |
|------------|-----|------|
| id | uuid, PK | 主キー |
| project_id | uuid, FK → projects | 対象案件 |
| customer_id | uuid, FK → customers | 入金元顧客 |
| scheduled_date | date | 入金予定日 |
| scheduled_amount | numeric | 入金予定額 |
| status | text | 例：scheduled / delayed / uncollected / completed / discrepancy |
| is_confirmed | boolean | 入金予定が確定しているか（次の作業へのロックに使用） |
| changed_by | uuid, FK → auth.users, nullable | 変更権限を持つ責任者（変更時のみ記録） |
| created_at, updated_at | timestamptz | 作成・更新日時 |

- 既存の **project_payments**（着工金・中間金・完了金）は**実績**用として継続利用。入金**予定**は本テーブルで管理。

### 5.8 入金実績（deposit_performances）【入金管理・機能③】

入金予定に対する実際の入金記録。入金方法（振込・現金・ローン）を区別するため。

| 項目（案） | 型 | 説明 |
|------------|-----|------|
| id | uuid, PK | 主キー |
| deposit_schedule_id | uuid, FK → deposit_schedules, nullable | 紐づく入金予定 |
| project_id | uuid, FK → projects | 対象案件（集計・一覧用） |
| actual_date | date | 実際の入金日 |
| actual_amount | numeric | 実際の入金額 |
| deposit_method | text | 例：bank_transfer / cash / loan |
| loan_id | uuid, FK → loans, nullable | ローン入金の場合のローンID |
| recorded_by | uuid, FK → auth.users | 実績を記録したユーザー |
| created_at, updated_at | timestamptz | 作成・更新日時 |

- 既存 **project_payments** と役割が重複する場合は、移行方針に応じて **project_payments** を残しつつ本テーブルで「予定との突合・承認」を行うか、段階的に本テーブルへ統一するかを検討。

### 5.12 入金管理と権限（profiles の拡張）

- 既存の admin / user に加え、店長・経理・事務などのロールを拡張する場合は、profiles.role の値を拡張するか、役割用の関連テーブルを検討してください。

### 5.21 予算（budgets）【見積・予算連携・機能⑦】

|------------|-----|------|

### 5.22 原価確定・最終粗利益（projects の拡張）【原価・支払管理・機能④】

- **projects** テーブルに以下の項目を追加する案。
- `cost_finalization_status`（text）：例：pending / finalized（原価確定済み）
- `final_cost`（numeric, nullable）：確定した最終原価
- `final_gross_profit`（numeric, nullable）：確定した最終粗利益
- 現場に関連するすべての請求書チェック完了時に更新する。

### 5.23 カレンダー・本日の予定での入金予定表示（機能⑧）

- 新規テーブルは不要。**deposit_schedules** を既存の案件カレンダーまたは「本日の予定」一覧のデータソースに加え、入金予定をアイコン・一覧で表示する。
- 汎用のスケジュール・イベントを管理する場合は、`schedule_events` のようなテーブルを用意し、種別（案件・入金予定・訪問予定など）でフィルタする方法も可。

## 6. まとめ

- **既存機能**：認証・マスタ・案件・見積・入金（着工金・中間金・完了金の実績）・原価・経費・人件費・売上管理・作業確認チェック表・完工報告・控え・集計・レポートは現行のまま利用可能。  
- **追加機能（進捗管理）**：TOP の状態別一覧、問い合わせ登録・リピート、メール通知、電話・クレーム表示、発生元、フォロー履歴、失注記録、月次目標・達成率、部門別フローを ver2.0 で追加する。  
- **追加機能（入金管理・機能③）**：入金予定の作成・管理、入金予定未確定時の作業停止、入金予定変更の権限制限、未回収・入金遅れ・入金相違の監視・警告、資金繰り把握、経理資料・ローン記録・顧客請求書発行、部門別ワークフロー（営業・店長・経理・事務）を ver2.0 で追加する。  
- **追加機能（原価・支払・帳票・スケジュール連携・2C）**：業者請求書の自動入力・発注書連携、請求書回覧・確認が必要な請求書のピックアップ、現場経費の自動原価計上、業者への支払処理・支払確定、追加予算承認・原価確定、入金状況の可視化・催促・レポート、受注見込み・予算連携、標準単価表・端数処理・経費割合、カレンダーでの入金予定表示・本日の予定、入金・支払の帳票出力・Excel 等ダウンロード、業態設定・業者ラベルを ver2.0 で追加する。  
- **Supabase（進捗管理）**：既存テーブルはそのままに、**inquiries**・**origins**・**フォロー履歴**・**失注記録**・**staff_monthly_targets** の追加を想定。電話着信は **call_logs** 等を検討。  
- **Supabase（入金管理）**：**deposit_schedules**・**deposit_performances**・**deposit_discrepancy_approvals**・**invoices**・**loans** の追加を想定。入金まわりの権限は **profiles** の拡張または権限テーブルで対応。  
- **Supabase（原価・支払・帳票・スケジュール連携）**：**contractors（業者マスタ）**・**orders（発注）**・**contractor_invoices（業者請求書）**・**vendor_payments（業者への支払）**・**site_expenses（現場経費）**・**budget_approvals（追加予算承認）**・**standard_unit_prices（標準単価表）**・**order_forecasts（受注見込み）**・**budgets（予算）** の追加を想定。**projects** に原価確定ステータス・最終原価・最終粗利益の項目を追加。カレンダーでの入金予定表示は **deposit_schedules** を既存カレンダーに連携。

実装時は、追加テーブルの RLS・インデックス・画面・API を段階的に整備してください。
