# 要件定義書：工事業向け業務管理・経理アプリ

## 1. プロジェクト概要

### アプリ名
kannri-app（管理アプリ）

### 目的
工事案件ごとに以下を管理し、工事完了後に「粗利」「純利」を正しく算出できるアプリを構築する。

- **見積作成（お客様向け）**: お客様に提示する見積書
- **原価／人件費／経費（社内用）**: 社内のみで管理するコスト情報
- **進捗管理**: 案件のステータスを管理し、全体の進捗を把握する

### 想定利用者数
約 30 人

---

## 2. 基本コンセプト

| コンセプト | 内容 |
|------------|------|
| 案件単位で管理 | 工事（案件）を 1 つの単位として管理する |
| 情報の分離 | お客様に見せる情報と社内情報は完全に分離する |
| マルチデバイス対応 | iPad / PC の両方で使える UI |
| 権限管理 | 管理者（admin）と一般ユーザー（user）で権限を分ける |

## 3. 部門と案件

### 3.1 三部門

案件は以下の三部門に分類され、部門ごとに保持する情報が異なる。

| 部門 | 説明 |
|------|------|
| 配送 | 商品設置・配送に関する案件 |
| 工事 | 工事に関する案件 |
| 修理 | 修理に関する案件 |

### 3.2 共通必須項目（全部門）

| 項目 | 説明 |
|------|------|
| 顧客名 | 顧客の氏名 |
| 顧客カナ名 | 顧客名のふりがな |
| 住所 | 顧客住所 |
| 電話番号 | 連絡先電話番号 |
| 工事種別 | エアコン / 工事 / 配送 から選択（部門とは独立して選択） |
| 部門 | 配送 / 工事 / 修理 から選択（工事種別とは独立して選択） |
| 案件番号 | 部門ごとに頭文字を変えて自動採番（工事=K、修理=S、配送=H など、即座に判別できる形式） |
| 担当者 | 担当者マスタから選択 |
| 着工日 | 工事・修理は着工日、配送は設置訪問日。カレンダー式で選択 |
| 完了予定日 | 完了予定日。カレンダー式で選択 |
| 備考欄 | 自由入力 |

※ 着工日・完了予定日は日付ピッカー（カレンダー形式）で選択する。

### 3.3 部門別の追加項目

**配送部門**のみ以下の追加項目あり。工事・修理部門は現時点では共通項目のみ。

| 項目 | 説明 |
|------|------|
| 設置商品 | 設置する商品名 |
| 品番 | 商品品番 |
| 色 | 色 |
| 数量 | 数量 |
| 保証書の有無 | 保証書あり / なし |

### 3.4 案件ステータス

| ステータス | 説明 |
|------------|------|
| 見積作成中 | 見積を作成している段階 |
| 見積送付済み | 見積書を送付済み |
| 作業中 | 工事・配送・修理を実施中 |
| 完了 | 完了 |
| キャンセル | キャンセル |

### 3.5 案件と工事の関係

1 案件＝1 工事として扱う。

### 3.6 顧客・企業マスタ

- **種別**：企業 / 個人 から選択する
- **企業**：企業リストに登録。担当者名（自由入力）も登録する
- **個人**：個人顧客として登録
- **再利用**：同一顧客・同一企業からの 2 回目以降の依頼は、既存の登録情報を再利用する
- **閲覧権限**：顧客登録情報の閲覧は管理者のみ可能

### 3.7 担当者マスタ

| 項目 | 説明 |
|------|------|
| 氏名 | 担当者名 |
| 電話番号 | 連絡先 |
| 所属 | 所属部門など |

案件の担当者は担当者マスタから選択する。

## 4. 業務フロー

1. 管理者または一般ユーザーが「案件（工事）」を作成（顧客・企業はマスタから選択または新規登録）
2. 案件に対して見積を作成する
3. **見積承認フロー**：管理者が承認する
4. 承認後、お客様向け見積書を PDF で送付  
   ※ 見積書には原価・人件費・経費は表示しない  
   ※ 見積書・請求書など外部への送付は原則管理者のみ
5. 依頼者が見積内容を了承したら「受領」ボタンを押し、請求書発行画面へ遷移
6. 工事・配送・修理を実施
7. 作業中、発生する都度 原価（材料費など）・経費（高速代など）を入力。売上も変動する
8. 案件ステータスを「完了」にする
9. **売上管理票**に遷移し、最終的な原価・経費・人件費を入力して**確定**
10. システムが粗利・純利を自動算出
11. 案件別・月別・担当者別に集計・確認できる

### 進捗管理

- 各案件にステータス（見積作成中、見積送付済み、作業中、完了、キャンセル）を付与
- 一覧画面などで進捗状況を確認し、滞留案件の発見や優先度の判断に活用する

## 5. 見積・請求書

### 5.1 見積の構成

- **明細形式**：項目 + 単価 + 数量 + 小計 の行単位
- **修正履歴**：修正版も残す（履歴管理する）

### 5.2 見積承認フロー

- 見積書発行・送付前に管理者の承認が必要
- 承認後にお客様へ送付可能

### 5.3 請求書の発行

- **タイミング**：依頼者が見積内容を了承したとき
- **受領ボタン**：見積画面に「受領」ボタンを配置。押下で請求書発行画面へ遷移
- **フォーマット**：見積書と同じ。タイトルを「見積書」「請求書」と切り替えるのみ

---

## 6. 原価・人件費・経費

### 6.1 原価

| 区分 | 入力方法 |
|------|----------|
| 材料費 | 選択 |
| その他 | 選択し、内容は自由入力 |

### 6.2 人件費

- **入力単位**：作業者名 + 単価
- 複数作業者分を登録可能

### 6.3 経費

| 区分 | 入力方法 |
|------|----------|
| 交通費 | 選択 |
| 高速代 | 選択 |
| 宿泊代 | 選択 |
| その他 | 選択し、内容は自由入力 |

---

## 7. 売上・損益

### 7.1 売上

- 当初は見積・請求書と同じ金額で開始
- 作業中に追加発生（高速代、材料費など）により**売上は変動する**

### 7.2 損益計算の定義

| 項目 | 定義 | 計算式 |
|------|------|--------|
| 売上 | お客様に請求する金額（変動あり） | - |
| 原価 | 材料費・その他 | - |
| 粗利 | 売上から原価を差し引いた利益 | 売上 − 原価 |
| 純利 | 粗利から人件費・経費を差し引いた利益 | 粗利 − 人件費 − 経費 |

### 7.3 確定の流れ

1. 案件ステータスを「完了」にする
2. **売上管理票**画面に遷移
3. 最終的な原価・経費・人件費を入力
4. **確定**する

※ 確定後も管理者・一般ユーザーともに数値の修正は可能

---

## 8. 入金情報

- **着工金**：着工時の入金
- **中間金**：中間時点の入金
- **完了金**：完了時の入金
- **合計**：着工金 + 中間金 + 完了金

※ 入金情報の閲覧は管理者のみ可能

## 10. 技術スタック・ユーザー管理

### 10.1 技術スタック

| 項目 | 技術 |
|------|------|
| フロントエンド | Next.js（App Router）、TypeScript、Tailwind CSS |

### 10.2 ログインユーザー

- **ロールの割り当て**：アカウント作成時に管理者（admin）または一般ユーザー（user）を指定
- **担当者マスタ**：ログインユーザーとは別。案件担当者（現場担当など）を管理するマスタ
