# 見積テーブル設計

## 概要

見積・請求書機能のためのテーブル設計です。

## テーブル構成

### estimates（見積ヘッダー）

| カラム | 型 | 説明 |
|--------|-----|------|
| id | uuid | 主キー |
| project_id | uuid | 案件ID（projectsへの外部キー） |
| version | integer | バージョン番号（履歴管理用、1から開始） |
| status | text | ステータス（draft=下書き, pending_approval=承認待ち, approved=承認済み, sent=送付済み） |
| approved_by | uuid | 承認者ID（profilesへの外部キー、NULL可） |
| approved_at | timestamptz | 承認日時（NULL可） |
| created_at | timestamptz | 作成日時 |
| updated_at | timestamptz | 更新日時 |

### estimate_items（見積明細）

| カラム | 型 | 説明 |
|--------|-----|------|
| id | uuid | 主キー |
| estimate_id | uuid | 見積ID（estimatesへの外部キー） |
| item_name | text | 項目名 |
| unit_price | numeric(10,2) | 単価 |
| quantity | numeric(10,2) | 数量 |
| subtotal | numeric(10,2) | 小計（単価×数量、自動計算可） |
| display_order | integer | 表示順序 |
| created_at | timestamptz | 作成日時 |
| updated_at | timestamptz | 更新日時 |

## 履歴管理

- 同じ案件に対して複数の見積バージョンを作成可能
- `version` フィールドでバージョン管理
- 最新バージョンは `version` が最大のもの

## 承認フロー

1. `status = 'draft'`: 下書き
2. `status = 'pending_approval'`: 承認申請（管理者の承認待ち）
3. `status = 'approved'`: 承認済み（管理者が承認）
4. `status = 'sent'`: 送付済み（お客様へ送付）

## RLS ポリシー

- 認証済みユーザーは見積の作成・編集が可能
- 管理者は全見積の閲覧・承認が可能
- 一般ユーザーは自分の担当案件の見積のみ閲覧可能
